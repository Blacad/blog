欢迎来到 Blacad 的个人博客。本站现在使用 Hexo 的 Icarus 主题，并在其上加入了取自个人头像色彩的定制样式：个人资料与内容索引位于左栏，文章目录悬挂在右栏，阅读长文时无需反复返回页面顶部。网站同时支持站内搜索、代码复制、分类、标签和 GitHub 评论。

日常写作主要发生在 `source/_posts/`；站点设置与主题设置分别位于 `_config.yml` 和 `_config.icarus.yml`。

## 开始写一篇文章

在项目目录执行：

```bash
pnpm exec hexo new post "my-first-post"
```

命令会创建 `source/_posts/my-first-post.md`，并同时创建同名资源目录。建议文件名使用简短的英文或拼音，它会成为稳定、易分享的文章地址；文章标题仍然可以写中文。

每篇文章开头都有一段 Front-matter，用来描述文章：

```yaml
---
title: 我的第一篇文章
date: 2026-09-09 10:00:00
updated: 2026-09-09 10:00:00
categories:
  - 技术
  - 前端
tags:
  - JavaScript
  - Hexo
description: 一句话说明文章解决了什么问题。
comments: true
---
```

正文使用 Markdown。首页会把 `<!-- more -->` 之前的内容作为摘要；如果不写这行，主题会自动截取一段文字。文章中的二级、三级标题会自动组成目录。

## 分类与标签怎么用

分类适合表示文章所属的长期栏目，数量应当少而稳定，例如“技术”“读书”“生活”。上面的数组写法会形成“技术 / 前端”的层级分类。

标签适合描述一篇文章涉及的具体主题，可以更灵活，例如“JavaScript”“性能优化”“旅行”。一篇文章通常选择一个分类、两到五个标签就足够了。

一个实用的判断方法是：如果它适合出现在网站主目录里，就用分类；如果它更像检索关键词，就用标签。发布后，分类和标签页面会由 Hexo 自动生成，不需要手动维护列表。

## 插入图片和其他资源

站点已经开启文章资源目录。创建 `my-first-post.md` 时，会同时得到 `source/_posts/my-first-post/` 文件夹，把图片放进去后可以这样引用：

```markdown
![图片说明](example.png)
```

图片文件名建议使用英文小写与连字符，例如 `search-panel.png`。提交前压缩体积，并为图片填写准确的替代文字，移动端加载会更快，也更利于无障碍阅读。

网站当前的个人头像文件是 `source/img/Blacad.jpg`。它同时用于导航栏标志、浏览器图标、PWA 图标、个人资料头像和结构化数据标志；如需更换，直接替换这张图片并保持文件名不变即可。

## 左右侧栏与文章目录

桌面端文章页采用三栏布局：个人资料、最新文章、分类与标签在左边，正文在中间，目录单独位于右边。右栏设置为悬挂状态，并限制在浏览器可视高度内；长目录可以在右栏内滚动，不会因为正文向下阅读而消失，也不会靠不断拉长侧栏来维持显示。

侧栏内容在 `_config.icarus.yml` 的 `widgets` 中配置。左栏部件使用 `position: left`，目录使用 `position: right`；`sidebar.right.sticky: true` 负责启用悬挂。手机和较窄的屏幕会自动隐藏固定右栏，可使用导航栏中的目录按钮打开目录。

## 本地预览与发布

写作时启动本地预览：

```bash
pnpm run server
```

浏览器访问终端显示的地址即可。保存 Markdown 后页面会自动重新生成。提交前建议再做一次完整构建：

```bash
pnpm run clean
pnpm run build
```

确认没有报错后，把修改提交并推送到 `main` 分支。仓库现有的 GitHub Actions 会自动构建并发布到 GitHub Pages。

## 搜索如何工作

Icarus 的 Insight 搜索会在构建时生成 `content.json`，其中包含本站文章、分类和标签的可搜索文本。点击导航栏右上角的搜索图标，输入标题、正文关键词、分类或标签即可查看匹配结果。

搜索在浏览器本地完成，不依赖 Algolia 等外部搜索服务。发布新文章后，只要网站重新构建，搜索索引也会同步更新。

## 启用评论区

文章底部使用 [Utterances](https://utteranc.es/) 将每篇文章的评论保存为 GitHub Issues。当前评论仓库已经指向 `Blacad/blog`，还需要完成一次授权：

1. 确认 `Blacad/blog` 是公开仓库，并已启用 Issues。
2. 打开 Utterances 网站，安装 GitHub App，并只授权给这个博客仓库。
3. 重新打开任意文章，评论框会自动出现；首次留言时 Utterances 会创建对应 Issue。

若以后更换仓库，在 `_config.icarus.yml` 中修改 `comment.repo`。某篇文章不想开放评论时，在文章 Front-matter 中写 `comments: false`。

## 样式与主题如何维护

项目通过 `hexo-theme-icarus` 依赖使用官方主题，不要直接修改 `node_modules/hexo-theme-icarus/`，因为重新安装依赖会覆盖里面的内容。

本站的配色、卡片、排版、头像和悬挂目录样式都集中在 `source/css/custom.css`，并由 `scripts/inject-custom-style.js` 自动加载。需要调整视觉效果时修改这个 CSS 文件即可；升级 Icarus 后也更容易保留自己的设计。

根目录 `_config.yml` 管理 Hexo 本身，包括站点标题、网址、文章链接格式和构建规则；`_config.icarus.yml` 管理导航、个人资料、侧栏、搜索、评论和页脚。尤其不要在已有大量文章后频繁修改 `permalink`，否则旧链接会失效。

## 发布前检查清单

- 标题能否准确说明文章主题，摘要是否在首页完整可读。
- 分类是否沿用已有栏目，标签是否具体且不过量。
- 图片是否压缩、路径是否正确、替代文字是否有意义。
- 代码块是否注明语言，本地构建是否成功。
- 文中的外部链接是否有效，敏感信息是否已经移除。
- 预览桌面和手机宽度，确认目录、表格和代码没有溢出。

以后不必为了“写得完整”才发布。先记录一个真实问题和可靠结论，再随着实践更新文章，博客会自然长成自己的知识地图。
