C/C++ 动态链接既是它的优点，又是它迁移困难的主要痛点之一。
本篇文章不介绍动态链接的具体原理，只是说明 C/C++ 动态链接为什么常常出现问题。

<!--more-->

## 静态链接与动态链接

静态链接

- 编译时把所依赖的库都链接到可执行文件中
- 运行时无需加载依赖库
- 可执行文件可能会比较大

动态链接

- 运行时加载依赖库
- 可执行文件通常会小很多

## 为什么动态链接容易出错

具体来讲，动态链接的可执行文件会包含一个动态链接库的索引表，这个索引表会告诉运行时环境，哪些库需要被加载。
而这些库可能需要依赖机器的系统库，在 Linux 下 是 `.so` 文件，在 Windows 下是 `.dll` 文件
如果系统库不支持或者版本不匹配就会报错

而静态链接在编译时就将所有依赖库都打包进了可执行文件中，在运行时不会依赖外部的库

可以形象理解为：
- 动态链接：编译、链接生成可执行文件时，只记录程序依赖哪些共享库以及需要哪些外部符号，而不把这些库的代码直接复制到可执行文件中。程序启动或运行时，由动态链接器找到对应的 .so / .dll，将其加载（映射）到进程地址空间，并完成符号解析。因此，如果目标机器缺少对应动态库，或者库的版本、符号、ABI 不兼容，就可能无法正常运行。
- 静态链接：链接阶段直接从静态库中提取程序所需要的目标代码，并复制到最终可执行文件中。因此程序运行时通常不再需要这些外部库，可执行文件更大，但部署和迁移通常更加简单。

## 编译、链接 与 装入

编译、链接 与 装入 三者往往一起出现。
严格看定义，编译将源代码转换成目标代码，链接将目标代码链接为可执行文件中，装入将可执行文件装入内存。

静态链接、动态链接
静态装入、动态装入
四者都不冲突，它们可以两两组合
- 链接考虑的是 要不要在链接阶段把所需代码并入最终可执行文件
- 装入考虑的是 模块是在程序开始前统一装入内存，还是在运行过程中按需装入内存
- 二者不是一个维度的事情

1. 静态链接 + 静态装入
- 程序在构建时就把所需库代码并入 executable
- 运行开始时把整个程序装入内存

2. 静态链接 + 动态装入
- 库代码已经在可执行文件里
- 但某些模块可以在运行时按需装入内存

3. 动态链接 + 静态装入
- 程序运行开始时，就把需要的共享库一起装入内存
- 但这些库并不是在链接阶段拷进 executable，而是运行时由动态链接器加载

4. 动态链接 + 动态装入
- 程序本体启动时先运行
- 某些共享库到需要时再加载，例如 dlopen / LoadLibrary


地址绑定与上述三者可以说关系其实也不大，地址绑定处理的是 逻辑地址 与 物理地址 的关系，只是时机可能和上述有点关系。
所谓的三种地址绑定时机，其实说明的是 逻辑地址 究竟是在何时转换成 真实物理地址的

| 绑定时机  | 程序中的地址              | 后续是否还转换      |
| ----- | ------------------- | ------------ |
| 编译时绑定 | 直接生成绝对地址            | 否            |
| 装入时绑定 | 先生成可重定位地址，装入时改成绝对地址 | 否            |
| 运行时绑定 | 保留逻辑/虚拟地址           | 是，由 MMU 动态转换 |
